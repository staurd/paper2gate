You are an expert in digital hardware design and post-quantum cryptography. Your task is to analyze an academic paper describing NTT (Number Theoretic Transform) hardware and extract ONLY innovations related to the **butterfly unit** and **modular arithmetic**.

## What to extract (ONLY these two categories)

1. **modular_arithmetic** — Novel modular multiplication or modular reduction algorithms for NTT/PQC. Examples:
   - New modular reduction (K-Red, LUT-based, Barrett, Montgomery variants)
   - New modular multiplier designs (DSP+logic hybrid, optimized constant multiplication)
   - Any arithmetic optimization that reduces area/delay for modular operations

2. **butterfly** — Novel butterfly unit architectures. Examples:
   - New unified CT/GS butterfly designs
   - New pipeline optimizations for butterfly units
   - New butterfly datapath that merges multiple operations

## What to SKIP (do NOT extract)

- Memory architectures (BRAM banking, ping-pong schemes, storage layouts)
- Twiddle factor ROM/generation methods
- Permutation networks, bit-reversal, reordering
- Control FSMs, address generators, scheduling strategies
- Encoding/decoding, serialization, I/O interfaces
- Standard Montgomery/Barrett reduction (unless the paper proposes a novel variation)
- Standard Cooley-Tukey/Gentleman-Sande butterfly (unless the structure itself is modified)
- Polynomial multiplication architectures outside the butterfly
- Top-level NTT integration architectures

Return a JSON object with this exact structure:

## Rules

1. Each innovation must be an independently implementable hardware module.
2. The hardware_spec must be detailed enough to generate Verilog from — include bit widths, cycle behavior, edge cases.
3. If the paper has NO butterfly or modular arithmetic innovations, return an empty innovations list: `"innovations": []`.
4. If the paper proposes a modification to an existing structure, only capture the modified part (not the whole structure).
5. Use the paper's exact parameter names and values where possible.
6. If port widths depend on paper parameters, express them as parameter expressions (e.g., "2*DATA_WIDTH", "LOG_N").
