# 第三章 Paper2Gate 框架

## 3.1 框架概览与设计原则

Paper2Gate 面向一个边界明确的自动化任务：从描述 Kyber 或 Dilithium 硬件实现的学术论文中识别作者提出的模乘或模约减创新，将其转换为结构化硬件规格，生成统一接口的 RTL 模块，并通过分层检查获得可追溯的功能和实现证据。本文不试图从论文中重建完整的 NTT、存储器、控制器或密码协议，而是选择模运算数据通路作为跨论文比较的最小硬件单元。

这一范围选择基于两个考虑。第一，模乘和模约减同时承载了论文的数学创新与硬件代价，能够在较小的模块上观察算法语义、位宽、流水线和资源之间的关系。第二，单一算术接口能够减少系统级控制逻辑和存储组织带来的干扰，使抽取误差、代码生成误差和验证误差可以被分别定位。因此，Paper2Gate 的核心问题不是“能否生成一段 Verilog”，而是“能否将论文证据转换为可执行的硬件规格，并在统一观察条件下检验生成结果”。

给定输入论文 $P$，框架形成如下转换链：

\[
P \xrightarrow{\text{证据解析}} E(P)
\xrightarrow{\text{规格归一化}} H
\xrightarrow{\text{RTL 生成}} V
\xrightarrow{\text{分层验证与综合}} C .
\]

其中，$E(P)$ 包含正文、页面级文本、图注和可选的图像证据；$H$ 是面向硬件实现的中间规格；$V$ 是统一接口的 RTL；$C$ 是由结构检查、语法检查、功能仿真和综合报告组成的证据集合。框架遵循三项设计原则：以论文证据而不是模型常识约束规格，以固定接口而不是自由端口保证跨论文可比性，以阶段状态而不是单一成功标签表达验证强度。

如图 3-1 所示，框架的主链路由证据解析、规格归一化、统一接口 RTL 生成和分层验证组成。证据不充分或目标方案存在歧义时，流程停止并保留待审状态；语法或功能失败则将诊断信息反馈给 RTL 修复阶段。底部证据链将论文来源、规格字段、RTL 版本与测试条件关联起来，使模块职责、设计依据和验证结论能够对应审阅。

**图 3-1 Paper2Gate 的总体框架。** 框架依次完成论文证据解析、硬件规格归一化、固定接口 RTL 生成和分层验证。结构与语法检查、黄金模型功能测试以及可选综合分别形成阶段证据；语法或功能诊断用于有界修复，而证据不足或方案不明确时停止推断并转入审阅。底部追踪链关联论文来源、规格字段、RTL 版本、测试条件和阶段状态。

## 3.2 论文证据处理与创新识别

**文本与页面证据。** 输入论文首先被转换为连续正文和按物理页划分的文本。连续正文用于方案识别和创新抽取，页面级文本用于保留证据的物理位置，并为图注筛选和图像分析提供页面映射。解析阶段只接受包含可提取文本层的 PDF；扫描型文档或文本层严重缺失的输入需要 OCR 或人工预处理，框架不自行猜测缺失内容。

**上下文控制。** 参考文献通常不包含当前设计的端口、时延或器件信息，却会占用语言模型上下文。框架只在参考文献标题位于全文末部且其后存在足够长的文本时裁剪文末引用：标题位于全文最后 35% 以内、且其后至少有 1,000 个字符时，才认为它是可信边界。方案识别使用裁剪正文的前 2,000 个字符；创新抽取使用运行配置规定的上下文上限，默认不超过 100,000 个字符。正文被截断时，提示明确告知模型后文不可见，并要求器件、实验时延和资源字段保持未知。

**方案 profile。** 方案识别在自动模式下返回 Kyber、Dilithium、unknown 或 mixed 及其证据；unknown 或 mixed 会停止后续生成，要求显式选择。显式选择只跳过分类，不改变后续可信常量。当前两个 profile 如表 3-1 所示。

| 方案 | 模数 $q$ | 操作数宽度 | 乘积宽度 | 默认验证延迟 |
| --- | ---: | ---: | ---: | ---: |
| Kyber | 3329 | 12 bit | 24 bit | 3 cycles |
| Dilithium | 8380417 | 23 bit | 46 bit | 5 cycles |

**表 3-1 方案 profile 的固定参数。** 这些常量不由语言模型推断，避免抽取错误改变密码学验证目标。

**图像证据。** 视觉分支采用“图注筛选—页面分析”的两阶段策略。文本模型先从图注中选择与模乘或模约减数据通路相关的图，排除 NTT、存储器、置换网络和无关控制结构；随后只渲染被选中的物理页面，并将图注、页面上下文和图像交给视觉模型。视觉模型只能读取可见的操作数、位宽、寄存器、常量、数据通路和流水级数，不得从图外知识补全字段。没有相关图时跳过视觉阶段，渲染或调用失败时保留文本抽取并将视觉证据标记为未验证。

**创新识别。** 抽取目标是一个作者提出且能够独立实现的模乘或模约减创新，包括新型约减算法、模乘结构、常数乘法优化和可独立映射为算术数据通路的修改。NTT、存储器、置换网络、地址生成、调度、编码解码、I/O、顶层控制以及作者未修改的标准 Montgomery 或 Barrett 实现均被排除。抽取器必须区分作者设计与引用基线；没有合格创新时返回空结果，存在多个无法唯一选择的候选时停止主流程。该限制使每个评测样本都对应一个清晰的生成目标。

## 3.3 规格归一化与 RTL 生成

**中间规格。** 论文级信息、模块级信息和硬件规格共同构成从文本到 RTL 的中间层。论文级信息保存方案、候选创新和作者实验器件；模块级信息确定目标类别和模块名；硬件规格保存参数、端口、行为、时序、约束、修正因子和延迟。与原始论文文字相比，中间规格把生成器和验证器需要执行的行为集中到可检查字段中，避免模型在代码阶段重新解释整篇论文。

**输出语义。** 不同论文可能输出普通模乘，也可能输出带缩放或符号的等价表示。框架统一表示为

\[
R=k\times(A\times B)\bmod q,
\]

其中 $k$ 是有符号整数。抽取器同时检查创新摘要、输出描述、行为、时序和约束，区分中间步骤的负常数与最终结果的负修正因子。只有负号明确作用于结果或输出时，才将修正因子归一化为负值。总延迟从输入 $A,B$ 有效计到输出 $R$ 有效，并包含产品寄存器；若约减逻辑之后有 $N$ 个额外寄存器，则总延迟为 $1+N$，未知时保留未知并在验证阶段使用 profile 默认值。

**统一接口。** 为比较约减逻辑而不混入端口差异，所有候选模块使用相同外部接口：

```verilog
module modmul(
    input         clk, rst,
    input  [DW-1:0] A, B,
    output [DW-1:0] R
);
```

`DW` 由方案 profile 固定为 12 或 23，模块名、时钟、复位、输入和输出不可由生成模型修改。接口内部划分为固定乘积前端和论文约减后端：前端使用 DSP 乘法器计算 $P=A\times B$ 并通过产品寄存器 $P_R$ 保存乘积；后端读取 $P_R$，执行论文约减逻辑并产生 $R$。固定前端提供共同起点，但不要求不同论文具有相同的内部约减电路。

**生成约束。** RTL 使用 Verilog-2001 和可综合表达。约减逻辑不得使用 `/` 或 `%` 直接表达模运算，也不得引入 `initial`、`$finish` 和 `$display` 等仿真结构。中间信号应覆盖真实数值范围而避免无必要的扩宽；条件加减优先将选择放在加法器输入；小常数乘法通过移位和相邻加减折叠；范围修正优先使用符号位或借位标志。生成结果先经过接口结构校验，结构不合规时最多进行两次定向重试，只有通过接口检查的模块才进入编译和功能阶段。

## 3.4 闭环验证与综合分析

**语法闭环。** 启用语法审查时，Icarus Verilog 对完整模块执行最多三轮编译。编译通过则结束语法检查；编译失败时，错误信息和当前 RTL 被反馈给修复模型，要求保留论文算法并修复语法或声明问题。修复结果必须再次通过接口校验，防止语法修复改变端口或流水结构。编译工具不可用时保留生成结果，但阶段标记为未验证；关闭语法审查时只执行结构校验。

**黄金模型验证。** 功能验证使用独立的参考计算

\[
R_{\mathrm{ref}}=(k\times A\times B)\bmod q .
\]

每个模块使用 32 个确定性向量，其中 4 个覆盖零值和模数边界，28 个由随机种子 42 生成，输入范围为 $[0,q-1]$。测试平台按照规格延迟采样输出；延迟未知或超出允许范围时使用 profile 默认值，并区分论文明确延迟和默认延迟。功能失败时，失败输入、期望值和实际值被反馈给修复模型，主流程最多进行三轮功能检查和修复。通过该测试集只能支持受测条件下的一致性，不能替代形式化等价证明。

**综合分析。** 综合目标依次取自实验指定、运行配置指定、论文作者实验器件和项目默认器件。论文只给出器件族或不完整型号时，使用预先固定的映射补全合法型号，并区分论文原文、工具补全和默认回退。Vivado 以统一的 `modmul` 模块为顶层，在指定器件和约束下提取 LUT、触发器、DSP、BRAM 和时序结果。资源数字只对器件、工具和约束一致的样本进行比较；工具不可用、执行失败或报告缺失不转换为零值。

**阶段状态。** 框架区分 `passed`、`failed`、`skipped`、`unverified` 和 `unavailable`：前者表示阶段获得预期输出，`failed` 表示明确失败，`skipped` 表示阶段未被执行，`unverified` 表示结果存在但缺少必要检查，`unavailable` 表示外部工具不可用。批量处理可以汇总时间和语言模型调用次数，但不同器件和不同约束下的物理资源不直接相加。

## 3.5 可审阅性与研究边界

Paper2Gate 将每次运行组织为从论文证据到硬件结论的数据血缘：原始论文经文本、页面和图像处理形成证据集合；证据集合经方案约束和创新识别形成硬件规格；硬件规格驱动固定接口 RTL；RTL 再进入结构、语法、功能和综合阶段。每一步都保留输入、输出和状态，使研究者能够判断错误来自论文理解、证据融合、规格归一化、代码生成还是外部工具。

可审阅性要求不同结果具有语义对应关系：论文中的延迟必须对应规格中的寄存器描述和验证平台的等待周期；功能通过必须对应方案常量、修正因子、测试向量和 RTL 版本；资源结果必须对应目标器件、综合约束和工具状态。任何单独的控制台输出或单个资源数字都不足以构成可复现的实验结论。

这一框架不直接生成完整 PQC 加速器，是因为完整系统会同时引入算法、存储和控制层面的不确定性，难以判断失败来源。将研究对象收缩到统一接口的模乘/模约减模块，可以在保留论文创新的同时建立清晰的证据链。下一章将在此基础上定义数据集、人工标注、对照组和评价指标。
