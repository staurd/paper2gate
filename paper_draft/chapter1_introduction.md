# 第一章 引言

## 1.1 研究背景

量子计算的发展正在改变传统公钥密码体制的安全假设。面向这一风险，后量子密码（Post-Quantum Cryptography, PQC）算法被设计为能够抵抗已知量子攻击，同时继续运行在现有的软件和硬件平台上。Kyber（现称 ML-KEM）和 Dilithium（现称 ML-DSA）是其中具有代表性的格密码方案，并已进入 NIST 后量子密码标准体系。与传统公钥算法相比，这类方案依赖更密集的多项式乘法、模乘和模约减操作，因此实现中的算术数据通路往往直接决定面积、时延和吞吐率。[文献待核验：NIST FIPS 203、FIPS 204 及相关算法文献]

FPGA 和 ASIC 硬件能够为 PQC 算法提供并行计算、流水线执行和专用数据通路，从而缓解软件实现中的性能瓶颈。围绕 Kyber 和 Dilithium 的硬件研究已经提出了多种模乘和模约减优化，包括常数乘法、移位加法、Barrett 或 Montgomery 类约减，以及针对不同器件的寄存器和流水线组织。此类创新通常不是以一个完整、统一的接口单独给出，而是分散在数学公式、算法伪代码、硬件结构图、时序说明和综合实验中。要将论文中的方法转化为可综合 RTL，读者必须同时理解密码学中的输出语义、算术中的数据范围以及硬件设计中的时序约束。

目前，这一转换过程主要依赖有经验的硬件工程师手工完成。工程师需要先确认论文描述的是作者自己的设计还是被引用的基线，再从不同章节中恢复模数、操作数位宽、修正因子、流水延迟和目标器件，最后据此编写和调试 Verilog。对于包含多个相似约减变体的论文，这一过程容易产生细微但关键的语义偏差。即使是经验丰富的硬件工程师，

大语言模型（Large Language Models, LLMs）为上述过程提供了新的自动化可能。LLM 可以从技术文档中提取结构化信息，也可以根据硬件规格生成 RTL 代码。然而，生成一段语法完整的 Verilog 并不意味着生成了正确的模运算实现。PQC 模乘模块还必须满足固定的数据宽度、输出语义、寄存器时序和可综合性要求；任何一个层面的错误都可能在后续仿真或综合阶段才暴露。因此，论文理解、规格归一化、RTL 生成和生成后验证不应被视为相互独立的单次任务，而应构成一个能够反馈和追溯的连续流程。

## 1.2 研究动机与现有缺口

从论文到硬件的自动化至少存在三个尚未解决的缺口。

首先，论文中的硬件知识具有明显的证据异构性。方案名称和模数通常出现在正文中，位宽和寄存器边界可能只出现在结构图中，时延和实验器件则常常位于实现章节或表格中。仅使用文本抽取会遗漏图中的关键证据，仅依赖视觉分析又难以稳定恢复公式和符号关系。因此，自动化系统需要在同一数据链中管理正文、页面级文本、图注和选定的图像证据，并保留这些证据与抽取字段之间的对应关系。

其次，不同论文对相似算术单元的描述缺少统一的比较接口。同一类模约减可能采用不同的中间变量、缩放因子和输出表示；如果生成模型自由设计端口和时序，算法差异、接口差异和模型偏差将被混合在一起，既难以自动检查，也难以比较资源结果。一个可行的自动化框架需要把密码方案的可信常量与论文提供的实现细节分开，并将不同论文映射到相同的外部接口。

最后，代码生成缺少与论文语义相匹配的闭环验证。语法检查只能说明代码可以被编译，不能说明代码实现了论文中的算术行为；单次仿真也无法解释错误来自规格抽取、时序理解还是 RTL 编写。若系统没有保存中间规格、错误反馈和修复版本，研究者也无法判断一个最终通过的模块究竟依据了什么证据。由此可见，论文到 RTL 的自动化不仅需要一个生成模型，还需要结构化的中间表示、明确的接口约束和能够区分不同失败状态的验证流程。

## 1.3 研究问题与问题边界

本文研究以下问题：给定一篇描述 Kyber 或 Dilithium 硬件实现的学术论文，能否自动识别其中作者提出的一个模乘或模约减创新，将其转换为结构化硬件规格和固定接口 Verilog 模块，并使用统一工具链产生可追溯的功能与资源证据？

本文不把“自动实现完整 PQC 算法”作为目标，而是选择论文中的模运算数据通路作为研究对象。对于每篇输入论文，系统尝试选择一个作者提出的 `modmul` 创新，将其行为表示为带方案参数的模乘语义，并生成满足固定端口约束的 Verilog 模块。论文中的 NTT 存储器、蝶形调度、地址生成、控制状态机以及完整的密钥封装或签名流程不属于本文的生成范围。

围绕这一问题，本文提出三个研究问题：

**RQ1：论文级硬件知识能否被准确抽取？** 本问题考察系统对目标方案、作者创新、模数、操作数宽度、输出修正因子、流水延迟和作者实验 FPGA 的识别能力，并进一步分析错误来自正文、公式、图表还是作者归属判断。

**RQ2：固定接口和闭环验证能否提高 RTL 生成质量？** 本问题比较首次生成和反馈修复后的结果，关注接口合规率、Verilog 编译通过率、黄金模型功能通过率、修复轮数和处理时间，并区分语法通过、功能通过与综合可用等状态。

**RQ3：不同系统组件对结果的贡献是什么？** 本问题通过关闭视觉证据、语法修复、功能修复，或使用人工正确规格作为输入等对照，分别评估证据抽取、接口归一化和验证反馈对端到端结果的影响。

## 1.4 Paper2Gate 的基本思路

Paper2Gate 将论文到 RTL 的转换组织为一条可检查的数据链。系统首先使用 PDF 解析器提取全文、逐页文本和图注，并根据图注筛选与模乘或模约减相关的页面。在视觉分支启用时，系统进一步从这些页面中补充操作数、寄存器、常量和流水线等信息。随后，方案分类器确定输入属于 Kyber 或 Dilithium，创新抽取器从正文和视觉证据中识别作者提出的模块，并过滤掉不属于目标模运算的系统组件或引用基线。

抽取结果被转换为三个层次的结构化表示。`PaperAnalysis` 保存论文标题、创新列表和作者实验器件；`ModuleSpec` 标识待生成模块的类别和摘要；`HardwareSpec` 保存端口、位宽、行为、时序、约束、修正因子和延迟等生成所需字段。方案 profile 为 Kyber 和 Dilithium 提供固定的模数、数据宽度和默认验证延迟，避免让 LLM 自由猜测密码学常量。

为保证不同论文之间的可比性，Paper2Gate 将候选实现统一映射到 `modmul` 外部接口。固定骨架提供乘法器和产品寄存器，模型主要负责根据论文描述生成从产品寄存器到输出端口的模约减逻辑。规格中的 `correction_factor = k` 明确表示输出语义 `R = k * (A * B) mod q`，其中 `k` 的符号必须与论文最终输出保持一致；`latency_cycles` 则表示从输入有效到输出有效的总周期数。

生成模块随后经过接口检查和 Verilog-2001 规则检查，并使用 Icarus 进行编译。编译失败时，错误日志被反馈给语法修复步骤；编译通过后，系统根据结构化规格和方案参数使用 Python 黄金模型计算期望结果，再用确定性测试向量检查生成模块的输出。如果功能检查失败，系统将验证信息反馈给功能修复步骤，并重新生成受约束的模块。工具可用时，Vivado 进一步以 `modmul` 为顶层执行综合，输出 LUT、FF、DSP、BRAM 和时序报告。每个阶段的输入、输出和状态均被保存，形成从论文证据、硬件规格、Verilog 源码到验证和综合结果的可追溯链条。

上述流程提供的是模块级自动检查，而不是完整密码算法的形式化证明。功能验证覆盖的是规定的接口、方案常量、时延和测试向量；综合结果则取决于具体的器件、工具版本和综合脚本。本文将这些条件作为实验设置的一部分，并避免把有限测试或单元级资源数字外推为完整密码系统的正确性、吞吐率或安全性保证。

## 1.5 本文贡献

本文的贡献集中在 Paper2Gate 当前支持的 Kyber/Dilithium 模块级范围内。

1. **论文知识的结构化表示。** 建立从论文正文、页面和图表证据到 `PaperAnalysis -> ModuleSpec -> HardwareSpec` 的转换路径，显式保存模数、位宽、行为、修正因子、时延和器件等字段。

2. **面向模运算的固定接口归一化。** 为 Kyber 和 Dilithium 提供可信的方案 profile，并将不同论文中的模乘或模约减实现映射到统一的 `modmul` 接口，从而在相同的接口和密码学常量下比较生成结果。

3. **生成后的闭环检查与修复。** 将接口校验、Verilog 编译、Python 黄金模型验证和错误反馈修复连接起来，分别记录语法、功能和综合阶段的结果，而不是把所有状态压缩为一个“成功/失败”标签。

4. **可追溯的硬件证据链。** 保存文本和图像证据、结构化规格、Verilog、错误日志、综合报告和运行摘要，为错误定位、人工复核和实验复现提供依据。

## 1.6 主张边界与论文组织

本文只研究 Kyber 和 Dilithium 两类方案，并且每篇论文只选择一个可独立实现的模乘或模约减创新。本文所称“功能验证通过”，是指生成模块在规定接口、方案参数、时延和测试向量下与 Python 黄金模型一致；这一结果不等价于形式化验证，也不保证所有可能输入均正确。类似地，Vivado 报告中的资源和时序数据只对应指定的模块、器件、综合脚本和工具版本，不能直接代表完整 Kyber 或 Dilithium 加速器的系统性能。

本文其余部分组织如下。第二章介绍 Kyber 和 Dilithium 中与模运算硬件相关的背景、论文证据类型以及 RTL 生成和验证的基本概念。第三章详细描述 Paper2Gate 的 PDF 解析、创新抽取、规格归一化、Verilog 生成、闭环验证和综合流程。第四章给出论文数据集、人工标注、对照组、评价指标和实验控制条件。第五章按照 RQ1、RQ2 和 RQ3 报告抽取准确性、端到端生成质量、运行成本、硬件资源和消融实验结果。第六章讨论后量子密码硬件自动化、论文知识抽取、LLM 代码生成和 RTL 验证方面的相关工作。第七章讨论实验发现、适用边界、局限性和未来方向。第八章总结全文。

正式投稿前，本章中的背景性陈述需要补充经过核验的 Kyber/ML-KEM、Dilithium/ML-DSA、PQC 硬件实现以及 LLM/HDL 生成相关文献。当前版本不预先填写未经核验的参考文献编号，也不把尚未完成的实验结果写成既定结论。
